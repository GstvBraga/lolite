# LoLite

A small, fast desktop client for League of Legends. It replaces the Riot Client window and the heavy League client UI with one lightweight native window for the things you do every session: queue up, accept, pick/ban, and play.

- ~5.6 MB single `.exe`, ~85–90 MB RAM, ~0.1% of one core when idle (reacts to League's events instead of polling)
- Saves ~1.4 GB RAM versus running the normal Riot Client + League UI (1.7 GB vs 3.1 GB total)
- Cold start to "ready to queue" in ~25 s (the floor set by Riot's own backend)

## How it works

LoLite does **not** talk to Riot's servers or touch the game. It drives the official clients through the local APIs they already expose on `127.0.0.1` (the same APIs tools like Blitz and Porofessor use):

1. Starts `RiotClientServices.exe --headless` (no Riot Client window).
2. Waits for your saved login, then calls the Riot Client's "Play" endpoint to start League.
3. Closes League's UI (`/riotclient/kill-ux`) and keeps the League backend running headless.
4. Reads lobby / queue / champ select state from the League client API (`lockfile` auth) and sends the same requests the official UI sends.

League reopens its own UI after games and partway through champ select; LoLite closes it again unless you asked for it.

## Features

- Auto-launch League headless on open
- Queue picker and lobby creation, role selection, find match / cancel
- Ready check accept/decline, optional auto-accept
- Party invites with sender name and queue, taskbar flash on new invite
- Champ select: search, hover, lock in, ban, Arena Bravery
- Reconnect and play again
- **Friends** list (online only by default, **Show offline** toggle) and direct-message chat with unread counts
- English and Brazilian Portuguese (**Options → Language**; defaults to your League client's language)
- **Open full client** button for anything LoLite doesn't cover (rune editing, store)
- **Kill Riot** button: kills all Riot/League processes, optionally Vanguard too (see below)
- **Options → Improved layout**: themed layout with queue tiles and champion grid; off by default (classic layout)

## Requirements

- Windows 10/11
- Riot Client + League installed at `D:\Riot Games\` (paths are constants in `src/riot.rs`)
- A saved Riot login: log in once with **"Stay signed in"** ticked. If the session expires, LoLite shows a **Log in** button that opens the normal Riot Client login.

## Build

Needs Rust (stable) and the Windows SDK (`rc.exe`, used to embed the icon).

```sh
cargo build --release
```

Output: `target/release/lolite.exe`. To show it in Start search, create a shortcut in `%APPDATA%\Microsoft\Windows\Start Menu\Programs\`.

The icon is generated by a dependency-free script; rerun it after changing the design:

```sh
python assets/make_icon.py
```

## Project layout

| Path | Purpose |
|---|---|
| `src/riot.rs` | Lockfile parsing, local HTTP client, launching and killing Riot processes |
| `src/main.rs` | Background poller (state + launch flow), shared actions, classic layout |
| `src/fancy.rs` | Improved layout and its theme |
| `src/social.rs` | Friends list and chat (both layouts) |
| `src/i18n.rs` | English / Portuguese text helper |
| `scripts/bench.ps1` | Startup time + RAM: `-Mode full` (official client) vs `-Mode lolite` |
| `assets/make_icon.py` | Generates `lolite.ico` (exe) and `icon64.rgba` (window icon) |
| `build.rs` | Embeds the icon into the exe |

Settings are stored in `%APPDATA%\LoLite\settings.txt`.

## Kill Riot and Vanguard

**Kill Riot** force-closes every Riot Client and League process, including a running game. With **also Vanguard** checked, it also stops the `vgc` service and `vgtray` (asks for admin via UAC). The Vanguard kernel driver (`vgk`) cannot be stopped without a reboot; League restarts the service by itself the next time you play.

## Risk and disclaimer

LoLite only uses Riot's local client APIs, the same way well-known third-party tools do, and never reads or modifies the game process or game files. Riot considers the local client API unsupported and "use at your own risk"; there is no history of bans for normal use, but no guarantee either. Endpoints can change between patches and break features.
